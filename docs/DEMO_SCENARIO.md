# TAID 현장 검증 MVP 검수 시나리오

이 문서는 OpenAI API 키가 없는 기본 환경에서도 실제 입력 → 규칙 구조화 → D1 공유 저장 → 검토 → 승인 지식 검색이 작동하는지 확인하는 절차입니다. 준비된 합성 데이터는 `SAMPLE`, 실제 입력은 `RULES · 실제 입력` 또는 `LIVE AI`로 구분되어야 합니다.

## 사전 확인

1. 검수에 사용할 비식별 참여자 코드와 검토자 코드를 정합니다. 예: `PILOT-01`, `REVIEW-01`.
2. 이 코드는 기록 식별용이며 로그인이나 비밀번호가 아님을 확인합니다.
3. 실제 개인정보·고객정보·영업비밀을 입력하지 않습니다.
4. 사이트 접근 권한은 앱의 코드와 별개이므로 검수 기기가 해당 Sites 프로젝트에 접근 가능한지 먼저 확인합니다.

## 시나리오 A — API 키 없는 실제 입력과 공유 저장

1. `/app`에서 참여자 코드를 입력하고 `실제 작업 직접 입력`을 선택합니다.
2. 최대 240자 범위의 테스트용 작업지시·품목·공정·설비를 직접 입력하고 다음 단계로 이동합니다.
3. `한 번에 말씀해주세요` 화면에서 비기밀 테스트 회고를 직접 입력합니다.
4. 세 문항이 별도 답변란이 아니라 말하기 가이드로 함께 보이는지 확인합니다.
5. `전체 회고 구조화`를 누릅니다.
6. 오류나 SAMPLE 전환 없이 `규칙 기반 실제 입력` 또는 `RULES` 결과가 나타나는지 확인합니다.
7. 공정·설비가 입력한 작업 맥락과 동일하고, 원문에 없는 항목은 비어 있거나 확인 대상으로 표시되는지 확인합니다.
8. 문제 기록은 맥락과 증상이 있으면 수량·원인이 비어 있어도 저장 확인을 진행할 수 있는지 확인합니다.
9. 개선 기록은 맥락과 개선 내용·제안 조치·확인 결과 중 하나가 있어야 하며, 세 값이 모두 비면 안내가 나타나는지 확인합니다.
10. 원문과 구조화 결과를 대조하고 확인 체크 후 `검토 요청으로 저장`을 누릅니다.
11. 완료 화면에 `RULES · 실제 입력`과 `검토 대기`가 나타나는지 확인합니다.
12. 페이지를 새로고침하거나 같은 사이트를 다른 브라우저·기기에서 열어 같은 공유 기록이 승인함에 나타나는지 확인합니다.

## 시나리오 B — 승인과 반려의 단방향 처리

1. 승인함에서 시나리오 A의 기록을 선택합니다.
2. 검토자 코드를 입력하고 `확인하고 지식으로 승인`을 누릅니다.
3. 승인된 기록이 검토 대기 목록에서 빠지고 승인 지식 검색에 나타나는지 확인합니다.
4. 이미 승인한 기록을 다시 반려하거나 승인할 수 없는지 확인합니다.
5. 두 번째 실제 기록을 저장한 뒤 반려 사유 없이 `보완 요청`을 누릅니다.
6. 반려 사유가 필요하다는 안내가 나타나는지 확인합니다.
7. 사유를 입력해 반려하고, 해당 기록이 승인 지식 검색에는 나타나지 않는지 확인합니다.
8. 다른 브라우저·기기에서도 두 결정 상태가 동일하게 보이는지 확인합니다.
9. 승인 LIVE 카드의 증상이나 조치 핵심어로 `찾아보기`를 실행하고, 답이 해당 카드의 증상·원인·조치·결과로 구성되는지 확인합니다.
10. 근거 버튼이 실제 LIVE 카드 ID와 제목을 가리키며, 일치하는 카드가 없을 때 답을 만들어내지 않는지 확인합니다.

## 시나리오 C — 특이사항 없음과 중복 방지

1. 참여자 코드와 작업 맥락을 선택한 뒤 `이 작업은 특이사항 없음`을 누릅니다.
2. `참여 완료` 화면이 나타나고 지식 카드가 생성되지 않는지 확인합니다.
3. 녹음 누적 시간이 최대 `03:00`에서 종료되는지 확인합니다.
4. 같은 현지 날짜에 같은 참여자 코드·작업지시로 다시 완료합니다.
5. 참여 완료 행이 중복 생성되지 않고 기존 기록이 갱신되는지 확인합니다.
6. 공유 현황의 누적 회고에는 체크인이 한 건만 반영되는지 확인합니다.

## 시나리오 D — SAMPLE 격리

1. 새 기록에서 `마이크 없이 샘플로 체험`을 누릅니다.
2. 구조화·저장·승인·검색 전 과정에 `SAMPLE · AI 미사용` 표시가 유지되는지 확인합니다.
3. SAMPLE 카드를 저장하거나 로컬에서 승인해도 `LIVE KPI`의 기록·실제 구조화·승인 지식 수가 변하지 않는지 확인합니다.
4. 승인한 SAMPLE 카드가 검색 화면의 `SAMPLE 데모 지식 · LIVE KPI 제외` 구역에 나타나고 카드에도 `SAMPLE · AI 미사용`이 표시되는지 확인합니다.
5. SAMPLE 카드가 LIVE 키워드 요약의 근거로 사용되지 않는지 확인합니다.
6. 다른 브라우저·기기에서는 해당 로컬 SAMPLE 변경이 공유되지 않는지 확인합니다.
7. `데모 초기화` 후 SAMPLE 상태만 초기화되고 시나리오 A·B의 D1 공유 기록은 그대로 남는지 확인합니다.

## 시나리오 E — 선택적 AI 구조화

서버에 OpenAI API 키가 설정된 검수 환경에서만 진행합니다.

1. 새 실제 회고를 입력하고 `전체 회고 구조화`를 누릅니다.
2. 결과가 `LIVE AI`와 `근거 완전성 자체평가 · 정확도 아님`으로 표시되는지 확인합니다.
3. 원문에 없는 원인·조치·결과가 임의로 생성되지 않았는지 대조합니다.
4. 저장 후 다른 세션의 승인함에 나타나고, 승인 뒤 지식 검색에 나타나는지 확인합니다.

AI 키가 없을 때 `LIVE AI`처럼 표시되면 실패입니다. 키가 없는 기본 환경에서는 오류가 아니라 `RULES · 실제 입력`으로 계속되어야 합니다.

## 시나리오 F — 오류·재시도·모바일·개인정보 고지

1. 저장 직전에 네트워크를 끊어도 전사문과 구조화 초안이 유지되고 `다시 시도`가 나타나는지 확인합니다.
2. 네트워크를 복구하고 다시 저장해 카드가 한 건만 생성되는지 확인합니다.
3. 같은 저장 요청 식별자로 내용이 달라지는 비정상 재전송은 `409 IDEMPOTENCY_CONFLICT`로 거절되는지 API 자동 테스트 결과를 확인합니다.
4. 두 검토 화면에서 같은 카드를 동시에 열고 한쪽에서 먼저 처리했을 때 다른 쪽은 이미 처리되었다는 안내와 새로고침 동작을 제공하는지 확인합니다.
5. 360~390px 폭에서 맥락 선택부터 저장 완료까지 주요 버튼이 가려지지 않는지 확인합니다.
6. 녹음 버튼보다 앞에 개인정보·기밀정보 입력 금지와 원음 미저장 안내가 보이는지 확인합니다.
7. 상세 안내에 브라우저 음성 처리, AI 모드의 OpenAI 전송, LIVE 기록의 서버 저장, SAMPLE의 로컬 저장이 구분되어 있는지 확인합니다.

## 합격 기준

- OpenAI API 키 없이 실제 입력의 `RULES` 구조화와 D1 공유 저장 흐름을 완료할 수 있습니다.
- 저장한 실제 기록과 검토 상태가 새로고침·다른 브라우저·다른 기기에서도 일치합니다.
- 저장 재시도가 중복 카드를 만들지 않고, 체크인 재시도가 중복 참여를 만들지 않습니다.
- 승인·반려는 검토 대기에서 한 번만 가능하며 반려 사유가 저장됩니다.
- 승인된 LIVE 기록만 공유 지식·키워드 요약의 근거가 되고, 승인 SAMPLE은 별도 표시되며 실적에서 제외됩니다.
- 참여자·검토자 코드를 인증이나 로그인으로 오해하게 설명하지 않습니다.
- 세 문항은 각각의 필수 답변란이 아니라 한 번의 회고를 돕는 안내 가이드로 동작합니다.
