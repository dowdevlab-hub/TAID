# TAID 현장 검증 MVP 인수인계

## 1. 인수 대상

이 저장소는 실제 작업자 입력을 구조화하고 공유 검토까지 이어지는 현장 검증용 MVP입니다. 기본 흐름은 별도 AI 키 없이 작동하며, 실제 전사문을 규칙으로 구조화한 뒤 D1에 저장합니다.

현재 인수되는 범위는 다음과 같습니다.

- `/` 소개 홈페이지
- `/app` 참여자 코드 → 등록 작업 선택 또는 실제 작업 직접 입력 → 한 번의 3분 회고 → 구조화 → 작업자 확인 → 공유 저장 → 승인·반려 → 승인 지식 검색
- 세 질문을 별도 입력란이 아닌 한 번의 회고를 돕는 말하기 가이드로 제공
- 브라우저 Web Speech 지원 환경의 한국어 음성 인식과 직접 텍스트 입력
- API 키 없이 실제 입력을 처리하는 규칙 구조화
- 서버에 키가 있을 때 사용하는 선택적 OpenAI 구조화
- D1 기반 공유 기록, `특이사항 없음` 체크인, 검토 상태와 집계
- 승인 LIVE 카드 기반 키워드 요약과 별도 SAMPLE 검색 구역
- SAMPLE 카드와 LIVE 기록·KPI의 분리
- 자동 빌드·렌더링·구조화·D1 상태 전이 테스트

## 2. 현재 구조

```text
브라우저
├─ 홈페이지·MVP UI (React + Vinext)
├─ 음성→텍스트 (브라우저 Web Speech, 지원 환경만)
├─ SAMPLE 카드·로컬 UI 상태 (브라우저 저장소)
└─ 동일 출처 API 요청
   ├─ /api/structure → 기본 규칙 구조화 또는 선택적 OpenAI
   ├─ /api/records → D1 공유 기록 조회·멱등 저장
   ├─ /api/records/:id → 단방향 승인·반려
   ├─ /api/check-ins → D1 참여 완료 조회·갱신
   └─ /api/overview → SAMPLE 제외 집계

배포 기반
└─ Vite + Cloudflare Worker + ChatGPT Sites + D1
```

주요 위치는 다음과 같습니다.

| 위치 | 역할 |
| --- | --- |
| `app/page.tsx` | 소개 홈페이지 |
| `app/app/Workspace.tsx` | MVP 앱의 화면·상태·상호작용 |
| `app/api/structure/route.ts` | 규칙·AI 구조화 서버 경로 |
| `app/api/records/` | 공유 기록 저장·조회·검토 결정 |
| `app/api/check-ins/route.ts` | 참여 완료 조회·중복 없는 갱신 |
| `app/api/overview/route.ts` | SAMPLE 제외 집계 |
| `db/schema.ts` | D1 런타임 스키마 정의 |
| `drizzle/0000_taid_mvp.sql` | 배포·검토용 초기 마이그레이션 |
| `tests/rendered-html.test.mjs` | 렌더링·API·D1 계약 자동 검증 |
| `worker/index.ts` | Cloudflare Worker 진입점 |
| `.openai/hosting.json` | Sites 프로젝트와 `DB` 논리 바인딩 |

R2 파일 저장소는 사용하지 않습니다. 앱은 음성 원음 파일을 보관하지 않습니다.

## 3. 실행과 검증

요구 환경은 Node.js 22.13 이상입니다.

```bash
npm ci
npm run dev
```

OpenAI API 키가 없어도 실제 입력 기반 `rules` 구조화와 로컬 D1 흐름을 실행할 수 있습니다. 인수 직후 다음 검증을 실행하세요.

```bash
npm run lint
npm test
```

자동 테스트는 메모리 D1을 사용하므로 운영 데이터를 읽거나 변경하지 않습니다. 수동 검수는 [DEMO_SCENARIO.md](DEMO_SCENARIO.md)를 따릅니다.

## 4. 저장 데이터와 상태 규칙

D1에는 다음 데이터가 저장됩니다.

- 실제 전사문과 작업지시·품목·공정·설비
- 구조화 방식 `ai` 또는 `rules`, 구조화 결과, AI의 근거 완전성 자체평가값(정확도 미검증)과 확인 대상
- 참여자 코드, 작성·수정 시각
- `검토 대기`, `승인`, `반려` 상태와 검토자 코드·반려 사유
- `특이사항 없음` 참여 기록과 녹음 시간

기록 저장은 `client_request_id`로 멱등 처리되어 네트워크 재시도가 같은 카드를 중복 생성하지 않습니다. 같은 식별자와 같은 내용은 기존 기록을 반환하지만, 같은 식별자로 내용이 바뀌면 `409 IDEMPOTENCY_CONFLICT`를 반환합니다. 체크인은 `참여자 코드 + 작업지시 + 날짜`가 같으면 새 행을 추가하지 않고 갱신합니다. 날짜 키는 브라우저 현지 날짜의 `day-YYYY-MM-DD` 형식이며 녹음 시간은 클라이언트·API·D1 모두 0~180초만 허용합니다.

작업 맥락은 등록 목록에서 선택하거나 최대 240자의 작업지시·품목·공정·설비를 직접 입력할 수 있습니다. 저장 전 최소 확인 기준은 다음과 같습니다.

- 문제: 작업 맥락과 증상
- 개선: 작업 맥락과 개선 내용·제안 조치·확인 결과 중 하나
- 노하우: 작업 맥락과 전달할 조치

수량 필드는 선택 사항이지만 입력 시 숫자가 필요하며 불량 수량은 작업 수량을 초과할 수 없습니다. 자동 생성 제목은 최대 300자로 제한됩니다.

검토 상태는 `검토 대기 → 승인` 또는 `검토 대기 → 반려`만 허용합니다. 이미 처리된 기록은 다시 변경할 수 없습니다. 반려에는 사유가 필요합니다.

SAMPLE 카드는 합성 데이터이며 로컬 데모 흐름에만 사용합니다. 로컬에서 승인한 SAMPLE은 지식 화면의 `SAMPLE 데모 지식 · LIVE KPI 제외` 구역에만 표시됩니다. 공유 저장·LIVE 집계·LIVE 키워드 요약에는 포함되지 않습니다. `데모 초기화`는 로컬 SAMPLE 상태만 초기화하고 D1 공유 데이터를 삭제하지 않습니다.

## 5. 구조화 모드

`POST /api/structure`는 한 번의 3분 회고 전체 전사문과 공정·설비 문맥을 한 요청으로 처리합니다.

- 키 없음: 근거 문장과 수량을 투명한 규칙으로 추출하고 `mode: "rules"` 반환
- 키 있음: OpenAI Responses API의 엄격한 JSON 스키마를 사용하고 `mode: "ai"` 반환
- 준비된 체험: 서버 구조화와 구분되는 `sample`

규칙 모드는 AI를 가장하지 않으며 화면에 `RULES · 실제 입력`으로 표시됩니다. AI 모드에서는 서버만 키를 사용하고 요청에 `store:false`를 지정합니다. 어느 모드든 작업자는 저장 전에 원문과 구조화 결과를 확인해야 합니다.

지식 화면의 `KEYWORD RULE · RAG 아님` 기능은 질문 핵심어와 일치하는 승인 LIVE 카드에서 증상·원인·조치·결과를 가져와 요약합니다. 고정된 CNC 답변, SAMPLE 카드, 임의 생성 내용은 근거로 사용하지 않습니다. 유사도 수치와 조회수는 실제 계산 기능이 없어 화면에서 제거되어 있습니다.

## 6. 코드, 로그인, 사이트 접근 권한

참여자 코드와 검토자 코드는 작성자·검토자를 구분하기 위한 MVP용 식별값입니다. 비밀번호, 로그인 토큰, 권한 검증 수단이 아닙니다. 링크에 접근할 수 있는 사람을 역할별로 통제하는 기능은 앱에 없습니다.

사이트 접근 가능 여부는 ChatGPT Sites 프로젝트의 접근 정책으로 별도 관리합니다. 다음 항목은 서로 독립적입니다.

- GitHub 저장소 소유자·협업자
- 기존 Sites 프로젝트 소유자·접근 허용 사용자
- 앱 화면에 입력하는 참여자·검토자 코드

GitHub 저장소를 이전해도 Sites 주소, 공개 범위, D1 운영 데이터, 프로젝트 소유권은 자동으로 이전되지 않습니다. 통제된 파일럿을 넘어 운영하려면 앱 로그인과 역할별 권한을 추가해야 합니다.

## 7. 개인정보와 보안 경계

- 음성은 브라우저 또는 브라우저가 사용하는 음성 서비스에서 처리될 수 있습니다.
- 앱은 음성 원음 파일을 저장하지 않습니다.
- 실제 전사문·작업 맥락·구조화 결과·코드는 D1에 저장됩니다.
- AI 모드에서는 전사문이 OpenAI에 `store:false`로 전송됩니다.
- 실제 개인정보와 영업비밀을 입력하지 않는 통제된 검증 데이터만 사용해야 합니다.
- 현재 버전에는 동의 이력, 자동 보관 기간, 삭제 요청, 역할별 접근 제어, 완전한 감사 로그가 없습니다.

## 8. 선택적인 환경값

기본 기능에는 별도 환경값이 필요하지 않습니다. AI 모드를 사용할 때만 서버 측에 설정합니다.

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5-mini
```

비밀값은 Git에 넣지 않습니다. 현재 저장소는 Sites의 D1을 사용하며 Supabase 계정이나 키를 요구하지 않습니다.

## 9. 배포와 소유권

- GitHub로 이전되는 것은 코드와 Git 이력입니다.
- `.openai/hosting.json`의 `project_id`는 현재 Sites 프로젝트 식별자이지 소유권 증명이 아닙니다.
- 새 소유자가 독립 운영하려면 자신의 Sites 프로젝트·D1에 연결하고 배포해야 합니다.
- 다른 호스팅으로 옮길 수 있지만 D1과 Worker API 부분은 대상 환경에 맞게 교체해야 합니다.
- 저장소에는 별도 오픈소스 라이선스를 선언하지 않았습니다. 법인 간 권리 이전이 필요하면 계약 범위를 별도로 확인해야 합니다.

배포는 코드, D1 마이그레이션, 사이트 접근 정책을 각각 확인해야 합니다.

## 10. 남은 한계와 다음 검증

현장 검증 MVP 이후 별도 작업으로 다룰 항목입니다.

1. 앱 로그인, 공장·조직·역할별 권한
2. 개인정보 동의, 보관·삭제, 접근·감사 정책
3. 실제 현장 소음과 용어에서 STT·구조화 정확도 측정
4. API 요청 제한, AI 비용 상한, 모니터링과 복구 절차
5. 실제 RAG 검색과 중복·반복 이슈 분석
6. MES·ERP·센서 기준정보 연동
7. 응답률, 승인율, 재사용, 조치 완료와 ROI 검증

화면에 남아 있는 초기 SAMPLE 카드는 실제 생산 성과가 아닙니다. 키워드 요약은 승인 LIVE 카드의 문자열 일치 기능이며 실제 RAG나 의미 검색이 아닙니다.

## 11. 저장소에서 제외한 항목

- 원본 PPT, PDF, DOCX 및 분석용 원천 자료
- 실제 `.env`와 모든 비밀값
- 운영 D1 데이터와 백업
- 브라우저 SAMPLE 데이터
- `node_modules`, 빌드 산출물, 로컬 배포 캐시

원본 자료나 운영 데이터가 필요하면 저장소 밖의 별도 승인된 전달 경로를 사용해야 합니다.
