# TAID 데모 프로토타입 인수인계

## 1. 인수 대상

이 저장소는 TAID 아이디어의 화면과 핵심 사용자 흐름을 검증하기 위한 발표용 프로토타입입니다. 인수자는 별도 계정, 데이터베이스, API 설정 없이 `SAMPLE` 전체 여정을 로컬에서 실행할 수 있습니다.

현재 인수되는 범위는 다음과 같습니다.

- `/` 소개 홈페이지
- `/app` 작업 맥락 선택 → 3문항 회고 → 구조화 결과 확인 → 검토 요청 → 승인/반려 → 승인 지식 검색
- `특이사항 없음`을 AI와 지식 카드 없이 참여 완료로 기록하는 빠른 흐름
- 브라우저 Web Speech 지원 환경의 한국어 음성 인식과 직접 텍스트 입력
- 브라우저 `localStorage` 기반의 카드·상태 보존
- 선택형 `/api/structure` AI 구조화 코드
- 자동 빌드·렌더링·API 계약 테스트

## 2. 현재 구조

```text
브라우저
├─ 홈페이지 / 데모 UI (React + Vinext)
├─ 음성→텍스트 (브라우저 Web Speech, 지원 환경만)
├─ 카드·상태 (브라우저 localStorage)
└─ 선택형 요청 → POST /api/structure → OpenAI Responses API

배포 기반
└─ Vite + Cloudflare Worker + ChatGPT Sites 연결
```

주요 위치는 다음과 같습니다.

| 위치 | 역할 |
| --- | --- |
| `app/page.tsx` | 소개 홈페이지 |
| `app/app/Workspace.tsx` | 데모 앱의 화면·상태·상호작용 |
| `app/api/structure/route.ts` | 선택형 AI 구조화 서버 경로 |
| `app/globals.css` | 홈페이지와 앱의 반응형 스타일 |
| `tests/rendered-html.test.mjs` | 빌드 결과와 API 계약 자동 검증 |
| `worker/index.ts` | Cloudflare Worker 진입점 |
| `.openai/hosting.json` | 현재 Sites 프로젝트 연결 메타데이터 |

D1과 R2는 현재 모두 비활성화되어 있으며 실제 서버 DB나 파일 저장소를 사용하지 않습니다.

## 3. 실행과 검증

요구 환경은 Node.js 22.13 이상입니다.

```bash
npm ci
npm run dev
```

샘플 체험에는 `.env`가 필요하지 않습니다.

인수 직후 다음 검증을 실행하세요.

```bash
npm run lint
npm test
```

수동 검수는 [DEMO_SCENARIO.md](DEMO_SCENARIO.md)를 따릅니다.

## 4. 데이터와 상태

현재 상태는 한 브라우저 안에서만 유지됩니다.

- 카드: `taid-mvp-cards-v2`
- 특이사항 없음 참여: `taid-mvp-no-issue-checkins-v1`

GitHub 푸시, 새 배포, 다른 기기 접속으로 이 데이터가 이전되지 않습니다. 운영 데이터로 사용하면 안 됩니다.

음성 원음 파일은 앱이 저장하지 않습니다. 브라우저 음성 인식은 브라우저·운영체제·네트워크·현장 소음에 따라 달라질 수 있으므로 전사문을 사용자가 확인·수정하는 흐름을 유지해야 합니다.

## 5. 선택형 AI 경로

`POST /api/structure`는 3문항 전사문과 공정·설비 문맥을 구조화합니다. 서버 측 환경에 키가 있을 때만 호출이 성공하며, 응답 결과는 화면에서 `LIVE AI`로 구분됩니다.

현재 프로토타입의 합격 기준은 AI 경로가 아니라 `SAMPLE` 경로의 완주입니다. 키 미설정이나 요청 실패를 실제 AI 성공처럼 가장하지 않으며, 사용자가 명시적으로 샘플 전환을 선택해야 합니다.

## 6. 배포와 소유권

- GitHub로 이전되는 것은 코드와 Git 이력입니다.
- `.openai/hosting.json`의 `project_id`는 현재 Sites 프로젝트를 가리키는 식별자이며 소유권 증명이 아닙니다.
- 기존 Sites 주소, 접근 정책, 프로젝트 관리자 권한은 GitHub 저장소 이전만으로 넘겨지지 않습니다.
- 새 소유자가 Sites에서 독립 운영하려면 자신의 프로젝트로 연결·배포해야 합니다.
- Vercel로 옮길 경우 화면 코드는 재사용할 수 있으나 Sites/Cloudflare 진입점과 배포 설정은 대상 환경에 맞게 조정해야 합니다.
- Supabase를 추가할 경우 로그인, 조직/역할, 공용 데이터 모델, 저장 정책을 별도로 설계해야 합니다.
- 이 저장소에는 별도의 오픈소스 라이선스를 선언하지 않았습니다. 외부 법인 간 권리 이전이 필요하면 GitHub 권한과 별개로 계약·사용권 범위를 확인해야 합니다.

이번 GitHub 푸시는 현재 배포된 사이트를 재배포하거나 공개 범위를 변경하지 않습니다.

## 7. 명확한 한계

이 버전에는 다음 기능이 없습니다.

- 앱 자체 로그인, 조직·역할별 권한, 사용자 식별
- 공용 DB, 여러 사용자 간 동기화, 백업
- 동의 기록, 보관 기간 집행, 서버 감사 로그
- 실제 RAG 검색, ML 반복 패턴 탐지
- 실제 생산 KPI 계산, MES·ERP·센서 연동
- 공개 서비스용 API 호출 제한, 비용 한도, 봇 방어
- 현장 효용, 정확도, ROI의 실증 결과

화면의 KPI, 차트, 초기 카드, 규칙 기반 코치 답변은 모두 발표용 샘플입니다.

## 8. 다음 단계로 넘어가는 기준

프로토타입 발표 후 실제 현장 파일럿으로 넘어갈 때는 최소한 다음을 별도 작업으로 잡아야 합니다.

1. 참여자·공장·조직 단위 로그인과 역할 정의
2. 공용 DB와 작업지시·품목·설비 기준정보 연결
3. 개인정보 동의, 삭제·보관, 접근·감사 정책
4. API 인증, 요청 제한, 비용 상한, 모니터링
5. 실제 현장 용어·소음 환경의 STT/핵심필드 정확도 측정
6. 응답률, 완료시간, 승인·재사용, 조치 완료 등 파일럿 지표 수집

실제 RAG·ML·MES·센서 연동은 이 프로토타입의 완료 조건이 아닙니다.

## 9. 저장소에서 제외한 항목

- 원본 PPT, PDF, DOCX 및 분석용 원천 자료
- 로컬 분석 보고서와 작업 메모
- 실제 `.env`와 모든 비밀값
- 브라우저 `localStorage` 데이터
- `node_modules`, 빌드 산출물, 로컬 배포 캐시

원본 자료가 필요하면 저장소 밖의 별도 승인된 전달 경로를 사용해야 합니다.
