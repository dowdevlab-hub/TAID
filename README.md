# TAID 현장 검증 MVP

TAID는 제조 현장의 짧은 회고를 실제 입력 기반의 문제·개선·노하우 기록으로 구조화하고, 공유 저장·검토·승인 지식 검색까지 연결하는 현장 검증용 MVP입니다.

OpenAI API 키는 필수가 아닙니다. 키가 없으면 실제 전사문을 투명한 규칙으로 구조화하는 `RULES` 모드가 작동하고, 서버에 키가 설정된 경우에만 `AI` 모드를 사용합니다. 준비된 합성 데이터는 항상 `SAMPLE`로 구분됩니다.

## 현재 제공 범위

| 제공하는 것 | 아직 제공하지 않는 것 |
| --- | --- |
| 홈페이지와 모바일 대응 앱 | 앱 자체 로그인·조직별 권한 관리 |
| 참여자 코드와 등록 작업 선택 또는 실제 작업 맥락 직접 입력 | 참여자 코드 기반의 신원 인증 |
| 한 번의 3분 회고와 브라우저 음성 인식 | 운영 수준의 STT 품질 보장 |
| 실제 입력의 기본 규칙 구조화 | 실제 RAG·ML 패턴 분석 |
| 선택적인 OpenAI 구조화 | MES·ERP·센서 연동 |
| D1 공유 저장, 검토 대기, 단방향 승인·반려 | 운영 수준의 감사·보관·삭제 정책 |
| 승인 LIVE 지식 검색·키워드 요약과 D1 기반 현황 수치 | 실제 RAG·의미 검색 |
| 별도 표시·격리된 SAMPLE 승인 지식 체험 | 실제 생산 성과를 뜻하는 샘플 카드·차트 |

## 주요 화면과 서버 경로

- `/` — TAID 소개 홈페이지
- `/app` — 기록, 검토, 승인 지식 검색을 연결한 앱
- `POST /api/structure` — 실제 전사문 구조화. 기본은 `rules`, 키가 있을 때 `ai`
- `GET|POST /api/records` — 공유 현장 기록 조회·멱등 저장
- `PATCH /api/records/:id` — 검토 대기 기록의 단방향 승인·반려
- `GET|POST /api/check-ins` — `특이사항 없음` 참여 기록 조회·중복 없는 갱신
- `GET /api/overview` — SAMPLE을 제외한 공유 데이터 집계

## 빠른 실행

Node.js 22.13 이상이 필요합니다.

```bash
npm ci
npm run dev
```

터미널에 표시된 로컬 주소의 `/app`으로 접속합니다. 환경변수나 OpenAI API 키 없이도 실제 입력을 규칙으로 구조화하고 로컬 D1에서 공유 저장 흐름을 검증할 수 있습니다.

첫 확인 순서는 다음과 같습니다.

1. 참여자 코드를 입력하고 등록된 작업을 선택하거나 `실제 작업 직접 입력`으로 작업지시·품목·공정·설비를 입력합니다.
2. 한 번의 회고를 녹음하거나 전사문을 직접 입력합니다.
3. `전체 회고를 구조화`하여 `RULES · 실제 입력` 결과를 확인합니다.
4. 원문과 결과를 대조하고 검토 요청으로 저장합니다.
5. 승인함에서 검토자 코드와 함께 승인 또는 반려합니다.
6. 승인한 LIVE 기록이 지식 검색과 키워드 요약의 근거로 나타나는지 확인합니다.

준비된 발표 흐름만 보고 싶다면 `마이크 없이 샘플로 체험`을 사용할 수 있습니다. 로컬에서 승인한 SAMPLE 카드는 검색 화면의 `SAMPLE 데모 지식 · LIVE KPI 제외` 구역에 명확히 표시되며 공유 저장·LIVE 실적·LIVE 키워드 요약에서는 제외됩니다. 상세 절차는 [현장 검수 시나리오](docs/DEMO_SCENARIO.md)를 참고하세요.

## 데이터와 구조화 방식

실제 기록, `특이사항 없음` 참여 기록, 승인·반려 상태는 Sites가 연결한 Cloudflare D1에 저장됩니다. 따라서 같은 사이트에 접속한 다른 브라우저나 기기에서도 공유 데이터를 다시 불러올 수 있습니다. 브라우저 저장소는 SAMPLE 데이터와 로컬 UI 상태에만 사용합니다.

실제 기록의 최소 확인 기준은 기록 유형에 따라 다릅니다.

- 문제: 작업 맥락과 증상 필수
- 개선: 작업 맥락과 개선 내용·제안 조치·확인 결과 중 하나 필수
- 노하우: 작업 맥락과 전달할 조치 필수

작업·불량 수량은 원문에 없으면 비워둘 수 있지만, 입력할 경우 숫자를 포함해야 하고 불량 수량은 작업 수량보다 클 수 없습니다. 한 번의 회고와 체크인 시간은 클라이언트와 서버 모두 최대 180초입니다.

공유 기록 저장은 `clientRequestId`로 멱등 처리합니다. 같은 식별자와 같은 내용을 재전송하면 기존 기록을 반환하고, 같은 식별자로 다른 내용을 보내면 `409 IDEMPOTENCY_CONFLICT`로 거절하여 조용한 데이터 덮어쓰기를 막습니다.

구조화 방식은 명확히 구분됩니다.

- `RULES · 실제 입력` — API 키 없이 실제 전사문에서 근거가 확인되는 항목만 규칙으로 추출
- `LIVE AI` — 서버에 OpenAI API 키가 있을 때 실제 전사문을 JSON 스키마로 구조화
- `SAMPLE · AI 미사용` — 준비된 합성 데이터 체험. 공유 지표에서 제외

지식 화면의 `KEYWORD RULE · RAG 아님` 기능은 질문 핵심어와 일치하는 승인 LIVE 카드만 찾아 그 카드의 증상·원인·조치·결과를 요약합니다. 고정 답변이나 SAMPLE 카드를 근거로 사용하지 않으며 실제 RAG로 표현하지 않습니다.

AI 모드의 요청에는 `store:false`를 사용합니다. 앱은 음성 원음 파일을 저장하지 않지만, 브라우저 음성 인식 서비스가 음성을 처리할 수 있습니다. LIVE 기록에는 전사문·작업 맥락·구조화 결과·참여자 코드가 D1에 저장되므로 개인정보와 기밀정보를 입력하지 않아야 합니다.

## 코드와 접근 권한

참여자 코드와 검토자 코드는 기록의 작성자·검토자를 구분하기 위한 문자열이며 비밀번호나 인증 수단이 아닙니다. 현재 MVP에는 앱 자체 로그인이 없습니다.

사이트에 누가 접속할 수 있는지는 ChatGPT Sites 프로젝트의 접근 정책으로 별도 관리됩니다. GitHub 저장소 권한, Sites 접근 권한, 앱 내부의 참여자·검토자 코드는 서로 다른 개념이며 자동으로 연동되지 않습니다.

## 선택적인 AI 설정

기본 `RULES` 모드는 별도 설정 없이 작동합니다. AI 구조화를 시험할 때만 서버 측에 다음 값을 설정합니다.

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5-mini
```

비밀값은 Git에 커밋하거나 `NEXT_PUBLIC_` 변수로 노출하지 않습니다. 별도 Supabase 계정이나 키는 현재 MVP 실행에 필요하지 않습니다.

## 검증

```bash
npm run lint
npm test
```

자동 테스트는 배포용 빌드, 서버 렌더링, 직접 작업 입력 계약, 기본 규칙 구조화, 선택적 AI 계약, D1 멱등 저장과 충돌, 180초 체크인 한도, 체크인 갱신, 단방향 승인·반려, 반려 사유, SAMPLE 제외 집계·검색 구분을 검증합니다.

## 인수와 배포

- GitHub 저장소가 소스 코드의 기준입니다.
- `.openai/hosting.json`은 Sites 프로젝트와 D1 논리 바인딩을 정의하며 비밀키가 아닙니다.
- GitHub 소유권을 넘겨도 기존 Sites 주소·접근 정책·프로젝트 소유권은 자동 이전되지 않습니다.
- 새 운영자는 자신의 Sites 프로젝트와 D1에 연결해 독립 배포할 수 있습니다.
- 다른 호스팅으로 이전할 경우 D1 API와 Worker 진입점을 해당 환경의 데이터베이스·서버 방식에 맞게 교체해야 합니다.

자세한 구조와 한계는 [인수인계 문서](docs/HANDOFF.md)를 확인하세요.

## 저장소에서 제외한 것

원본 발표자료, 분석용 원천 파일, 실제 `.env`, API 비밀값, 운영 D1 데이터, 브라우저 로컬 데이터, 빌드 결과물은 저장소에 포함하지 않습니다.
