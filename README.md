# TAID Voice + Knowledge MVP

작업자의 짧은 음성 회고를 실제 AI로 구조화하고, 중요값 확인과 관리자 승인을 거쳐 재사용 가능한 현장 지식으로 전환하는 프로토타입입니다.

## 현재 작동하는 흐름

- `/`: TAID 제품 홈페이지
- `/app`: 작업자·관리자 통합 프로토타입 워크스페이스
- 공정·설비 선택 또는 QR 스캔 데모
- 지원 브라우저의 한국어 음성 인식과 텍스트 직접 입력·수정
- `POST /api/structure`: 전사문과 공정·설비 문맥을 OpenAI Responses API로 보내 정해진 스키마의 지식 초안을 생성
- AI가 정리한 품목·수량 등 중요값을 작업자가 재확인
- AI가 설정되지 않았거나 호출에 실패하면 오류를 명시하고, 사용자가 선택한 경우에만 샘플 결과로 계속 진행
- 검토 대기 → 승인/보완 요청, 승인 지식 검색과 파일럿 대시보드
- 저장한 카드와 검토 상태를 브라우저 `localStorage`에 보존

## 로컬 실행

Node.js 22.13 이상이 필요합니다.

1. 의존성을 설치합니다.

   ```bash
   npm ci
   ```

2. 예시 환경변수 파일을 복사하고 서버용 OpenAI API 키를 입력합니다.

   ```bash
   cp .env.example .env
   ```

   PowerShell에서는 다음 명령을 사용할 수 있습니다.

   ```powershell
   Copy-Item .env.example .env
   ```

   ```dotenv
   OPENAI_API_KEY=your_api_key_here
   OPENAI_MODEL=gpt-5-mini
   ```

   `OPENAI_MODEL`은 선택 사항이며, 생략하면 `gpt-5-mini`를 사용합니다. `OPENAI_API_KEY`는 서버에서만 읽으며 `NEXT_PUBLIC_` 접두사를 붙이거나 클라이언트 코드에 노출하면 안 됩니다.

3. 개발 서버를 실행합니다.

   ```bash
   npm run dev
   ```

추가 확인 명령은 다음과 같습니다.

```bash
npm run lint
npm run build
npm test
```

## 데이터와 개인정보 처리

- 앱의 AI 엔드포인트에는 녹음 원음이 아니라 음성 인식 후의 전사문과 선택한 공정·설비 문맥만 전달됩니다.
- OpenAI 요청은 `store: false`로 전송되며, 응답과 원문을 별도 서버 데이터베이스에 저장하지 않습니다.
- 사용자가 저장한 지식 카드는 현재 브라우저의 `localStorage`에만 남습니다. 다른 기기나 브라우저와 동기화되지 않으며 브라우저 데이터를 지우면 사라집니다.
- 브라우저 음성 인식의 지원 범위와 음성 처리 방식은 브라우저·운영체제에 따라 다릅니다. 마이크 권한을 거부하거나 미지원 환경에서는 텍스트를 직접 입력할 수 있습니다.
- 실제 현장 데이터에는 개인정보나 영업비밀이 포함될 수 있으므로, 운영 배포 전 수집 동의·보관 기간·삭제 정책을 확정해야 합니다.

## 프로토타입 경계

현재 버전에는 자체 회원가입·로그인, Supabase 같은 서버 데이터베이스, 조직별 데이터 격리, 역할 기반 권한, 서버 감사 로그가 없습니다. 음성 인식과 AI 구조화는 실제로 작동하지만, 나머지 검토·검색·대시보드 데이터는 단일 브라우저에서 제품 흐름을 검증하기 위한 데모입니다.

공개 서비스로 전환하기 전에는 API 호출 인증과 사용량 제한, 비용 상한, 악성 입력 방어, 조직별 권한·저장소, 원음 및 전사문 보관·삭제 정책, 감사 로그, 실패 재시도·작업 큐, 실제 공장 환경의 음성 인식 정확도 평가가 필요합니다.
